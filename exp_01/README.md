# Experiment 01 — ESP8266 (NodeMCU v2)

PlatformIO firmware project targeting **Espressif ESP8266** on the **NodeMCU v2** board (`nodemcuv2`). The toolchain uses the **Arduino** framework with **GNU C++20** (`-std=gnu++20`).

---

## Layout

| Path | Purpose |
|------|---------|
| `platformio.ini` | Board, platform, framework, and compiler flags |
| `src/` | Application source (e.g. `main.cpp` / `main.ino`) |
| `include/` | Shared headers (optional) |
| `lib/` | Private libraries vendored into this project |
| `test/` | PlatformIO unit tests |

After `pio init`, add firmware under `src/`. PlatformIO expects an entry point there (commonly `src/main.cpp`).

---

## Prerequisites

- **PlatformIO Core** installed and on your `PATH` (see repository root `README.md`).
- Your user in the **`dialout`** group for USB serial (logout required after `usermod`).
- **Hardware:** NodeMCU / Amica-class ESP8266; USB cable with data lines.

---

## Build, upload, monitor

Run these from **this directory** (`exp_01/`):

```bash
# Compile
pio run

# Upload firmware (device must be visible on a serial port)
pio run --target upload

# Serial monitor (115200 is common; override if you change Serial.begin)
pio device monitor
```

**Upload port:** If auto-detection fails, pass the port explicitly, for example:

```bash
pio run --target upload --upload-port /dev/ttyUSB0
```

For a persistent local port, prefer a **`platformio.local.ini`** (gitignored) — see root `.gitignore`.

## Neovim / clangd (LSP)

clangd embeds **Clang** and cannot target **Xtensa**, while PlatformIO builds with **`xtensa-lx106-elf-g++`**. This project uses the usual workaround:

1. **`compile_commands.json`** — generated by PlatformIO so `-I` / `-D` match the firmware build:

   ```bash
   pio run -t compiledb
   ```

   Run this after changing `platformio.ini`, adding libraries, or editing include paths. The file is gitignored; regenerate after clone or when LSP include paths look wrong.

2. **`.clangd`** — instructs clangd to:

   - use **`CompilationDatabase: .`** (the file above);
   - replace the compiler with **`Compiler: clang++`** so parsing runs as **x86_64** host C++;
   - **`Remove`** GCC/Xtensa-only flags (`-mlongcalls`, `-mtext-section-literals`, `-free`, `-fipa-pta`) that Clang does not understand (these caused the “unknown argument `-mlongcalls`” / bogus missing `Arduino.h` errors);
   - **`Diagnostics / Suppress`** a couple of cross-environment noise codes (`redefinition_different_typedef`, `pp_file_not_found`) so missing newlib paths on the host do not flood the editor while completion still works for typical Arduino APIs.

**Do not** put **`--query-driver`** inside `.clangd` `CompileFlags: Add` — it is not a compiler flag and will break parsing. If you later switch to driver-based setup, pass **`--query-driver=.../xtensa-lx106-elf-g++`** only on the **clangd** command line in your editor config.

Restart clangd after changing `.clangd` or `compile_commands.json` (e.g. Neovim `:LspRestart`).

## Step-by-step: Neovim + clangd (first time and refresh)

Follow these in order. All shell commands assume your current working directory is **`exp_01/`** (the folder that contains `platformio.ini` and `src/main.cpp`).

1. **Install the LSP server** (once per machine, if you do not already have it):

   ```bash
   sudo apt install clangd
   ```

2. **Put PlatformIO on your `PATH`** so `pio` works in a terminal (see the repository root `README.md` if you have not done this yet). Confirm with:

   ```bash
   pio --version
   ```

3. **Generate the compilation database** (required for correct includes and defines). Run this after clone, after any change to `platformio.ini`, or when you add or change library dependencies or include layout:

   ```bash
   cd ~/Embedded/exp_01
   pio run -t compiledb
   ```

   Adjust the **`cd`** path if your clone lives elsewhere; only the **`exp_01`** directory that contains **`platformio.ini`** matters.

   This creates or updates **`compile_commands.json`** in `exp_01/`. That file is listed in the root **`.gitignore`**, so it is not stored in git; you generate it locally.

4. **Keep the project `.clangd` file** in `exp_01/` as committed in this repository. It tells clangd to use the compilation database, swap in host **`clang++`**, strip unsupported Xtensa flags, and filter a few noisy diagnostics. Do not add **`--query-driver`** under `CompileFlags: Add` in that file.

5. **Start Neovim with the LSP** from the project (or open `exp_01` as the editor root) so the active file’s path is under `exp_01/`. Open **`src/main.cpp`**. Your config should start **clangd** for C++ (for example `nvim-lspconfig`’s `clangd` setup).

6. **Reload the language server** so it picks up a new or updated `compile_commands.json` or `.clangd`:

   - In Neovim, run **`:LspRestart`** (or the equivalent command your LSP plugin documents).

7. **Optional check** (from `exp_01/`, after `pio run -t compiledb`):

   ```bash
   clangd --check=src/main.cpp
   ```

   A clean run ends with **“All checks completed, 0 errors”** and exit status **0**.

8. **When to repeat steps 3 and 6:** after editing **`platformio.ini`**, adding **`lib/`** dependencies, changing **include** paths, or if diagnostics suddenly look wrong (missing `Arduino.h`, fake “undeclared identifier” for `pinMode` / `delay`, or unknown flags). Regenerate the database, then restart clangd.
